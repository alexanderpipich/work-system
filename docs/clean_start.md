# Чистый старт базы (П1)

Порядок запуска work-system на пустой базе для новой компании. Старая база после этого не нужна: справочники лежат в репозитории (`data/reference/*.json`), сотрудники и карты загружаются из файла авансов, смены — штатным загрузчиком.

## Где запускать скрипты

Скрипты (`scripts/…`, `tools/…`, `create_admin.py`) работают с той базой, на которую указывает `DATABASE_URL`. Для прода есть два варианта:

- **Консоль приложения в Timeweb**, если она доступна: команды запускаются из корня приложения, `DATABASE_URL` уже задан.
- **Локально из папки `work-system`** с `DATABASE_URL` прода. База должна принимать внешние подключения с вашего IP:

  ```bash
  export DATABASE_URL='postgresql+psycopg2://USER:PASSWORD@HOST:5432/DBNAME'
  ```

  В Windows PowerShell: `$env:DATABASE_URL='...'`. Переменная из окружения важнее значения в `.env`.

Все команды ниже выполняются из корня проекта.

## Шаги

### 1. Пустая база

В Timeweb создайте новую базу PostgreSQL. Либо очистите существующую (**все данные будут удалены безвозвратно**, сначала сделайте дамп):

```sql
DROP SCHEMA public CASCADE;
CREATE SCHEMA public;
```

### 2. `DATABASE_URL`

Пропишите строку подключения к новой базе в настройках приложения Timeweb, а для локального запуска — в `.env` или в окружении.

### 3. Деплой

Сделайте коммит в `main`. Timeweb пересоберёт контейнер, и при старте приложение создаст все таблицы (`Base.metadata.create_all`).

Проверка: страница `/login` открывается.

### 4. Справочники

```bash
python scripts/seed_reference_data.py
```

Скрипт загрузит режимы гражданства, страны, типы документов, правила режимов, услуги, магазины и их контакты, ставки, настройки мониторинга и рефералки, регионы. Он печатает по каждой таблице, сколько записей вставлено и сколько уже было. Повторный запуск ничего не дублирует: будет «вставлено 0».

**Режимы сида (П4.3):**

| Команда | Что делает |
|---|---|
| `python scripts/seed_reference_data.py` | Только добавляет недостающие записи. Существующие не трогает, даже если в JSON они другие: в отчёте «есть N (отличаются от JSON: M)» |
| `… --update` | Ещё и обновляет отличающиеся записи по JSON |
| `… --only stores,store_contacts` | Только перечисленные таблицы (можно вместе с `--update`) |

У магазинов при `--update` **уже известный город не перезаписывается**: город ТК должен совпадать с «Городом» из timebook, по нему подбираются ставки. Расхождения печатаются строками «ТК: city оставлен из базы …, в JSON …». Пустой город в базе берётся из JSON.

Контакты магазинов (`store_contacts.json`) привязываются по номеру ТК. Если такого ТК в базе нет, контакт пропускается — в отчёте «пропущено: нет ТК N». Создайте ТК («Наполнить из смен» на `/admin/stores`) и запустите сид ещё раз.

Образцы документов (картинки) в справочник не входят: их файлы утеряны при переезде на S3. Загрузите их заново в `/admin/document-types`.

### 5. Администратор

```bash
python create_admin.py --phone 79990000000 --name "Фамилия Имя Отчество"
```

Пароль скрипт спросит интерактивно. Его можно передать и через `--password` или `ADMIN_PASSWORD`, но тогда он останется в истории команд. Пароль помечается временным, после входа смените его. Если сотрудник с таким ФИО уже есть (например, заведён импортом), он получит логин и роль superadmin, второй пользователь не создаётся.

### 6. Юрлица

Войдите под администратором и заведите юрлица новой компании в разделе юрлиц. Из старой базы они не переносятся.

### 7. Сотрудники, ТМ и карты

Сначала сухой прогон (ничего не записывает, печатает отчёт):

```bash
python tools/import_employees_cards.py --file "Аванс_28.09.2026-04.10.2026.xlsx"
```

Проверьте отчёт:

- сколько сотрудников и ТМ будет создано;
- какие ТМ привязаны к существующим пользователям (строки `«…» → существующий …`);
- банки вне справочника алиасов;
- проблемные строки.

Затем запишите:

```bash
python tools/import_employees_cards.py --file "Аванс_28.09.2026-04.10.2026.xlsx" --apply
```

Сотрудники создаются без кабинета: без телефона и пароля, войти не могут. Кабинет выдаётся позже через `/admin/users/pending` (пачкой по сменам), `/admin/create-user` или загрузку пользователей таблицей.

### 8. Смены

Загрузите табель («Отчет об отработанных часах…») через `/admin/upload`. После загрузки ФИО из смен без кабинета появятся в `/admin/users/pending`.

### 9. Контроль дублей

```bash
python tools/check_duplicate_users.py
```

Ожидается вывод «дублей ФИО в users не найдено». На чистой базе уникальность ФИО обеспечивает индекс `uq_users_employee_name_norm`.

## Локально

Те же шаги с локальной базой. Для проверки удобно поднять отдельную базу, а не трогать рабочую `work_db`:

```bash
psql -U postgres -c "CREATE DATABASE work_db_clean"
export DATABASE_URL=postgresql+psycopg2://postgres:PASSWORD@localhost:5432/work_db_clean
uvicorn main:app --port 8000          # шаг 3: create_all; дальше можно остановить
python scripts/seed_reference_data.py
python create_admin.py --phone ... --name "..."
python tools/import_employees_cards.py --file "..." --apply
python tools/check_duplicate_users.py
```

## Что ещё учесть

- **Ставки.** В справочнике почти все ставки привязаны к Санкт-Петербургу и Ленинградской области, для Москвы ставка одна. Если работа идёт в Москве и других городах, заведите ставки в `/admin/rates` до расчёта выплат.
- **Скоупы городов выключены** (`SCOPES_ENABLED` не задан = `false`): ТМ, экономисты и кадровики видят все города. Чтобы вернуть прежние ограничения, задайте `SCOPES_ENABLED=true`.
- **Роль `hr_manager`** на новой базе не встречается. На старых базах её переводит в `tm` команда `python scripts/migrate_role_tm.py --apply`; без миграции `hr_manager` и так работает как ТМ.
- **Обновлять справочники в JSON** (для следующего чистого старта): `python scripts/export_reference_data.py` на базе-источнике, затем коммит изменений в `data/reference/`.
