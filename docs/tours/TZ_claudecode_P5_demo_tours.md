# ТЗ П5: демо-режим — туры по кабинету сотрудника и рабочему столу руководителя, доработки кабинета

**Проект:** work-system · **База:** `main` после П4.11 · **Дата:** 14.10.2026
Ветка `feat/p5-demo-tours`, коммиты по блокам A–E. Тексты туров — **утверждённые** файлы владельца, кладутся в репозиторий рядом с ТЗ: `P5_1_lk_employee_tour_text_v2.md` (кабинет сотрудника) и `P5_2_hr_lead_tour_v3.md` (руководитель). Текст из них берётся **дословно**; агент ничего не переформулирует. Решения владельца по v3: подпись роли `hr_lead` — **«Руководитель»**; в шаге «Что дальше» — **две плитки** (МВД и CRM), автозагрузку и «Коммуникации» убрать.

Правило проекта: расчёты не трогаем; тур — это слой поверх существующих страниц, он не меняет их разметку, кроме добавления `data-tour="…"` на якорные элементы.

## Блок A — движок туров (`static/tour.js`, `static/tour.css`, `templates/_tour.html`)

1. **Данные тура** — JSON в `data/tours/employee.json` и `data/tours/hr_lead.json`: `{"id": "hr_lead", "version": 1, "start_url": "/admin", "steps": [...]}`. Шаг — один из трёх типов:
   - `{"type": "screen", "title": "...", "body": "...", "tiles": [{"title","text"}]?}` — полноэкранная карточка без привязки к элементу (обложка, роли, «что дальше», финал); `tiles` — сетка плиток (роли — 7, «что дальше» — 2);
   - `{"type": "element", "anchor": "rail", "title": "...", "body": "...", "placement": "right|left|top|bottom"}` — подсветка элемента с `data-tour="rail"` и облачко рядом; если элемента на странице нет — шаг пропускается молча (чтобы тур не ломался на пустых данных), в консоль — предупреждение;
   - `{"type": "navigate", "url": "/admin/payouts/weekly"}` — переход на страницу; после загрузки тур продолжается со следующего шага.
   `body` — текст; переносы строк `\n` → абзацы. Никакого HTML в JSON.
2. **Многостраничность.** Состояние `{tourId, step, startedAt}` — в `sessionStorage`; `tour.js` подключён через `base.html` и кабинет сотрудника (оба макета) и на каждой загрузке страницы проверяет, есть ли активный тур и совпадает ли `location.pathname` с ожидаемой страницей текущего шага; если да — показывает шаг, если нет — закрывает тур (пользователь ушёл сам). `navigate` делает обычный переход (`location.href`), не fetch.
3. **Оверлей.** Затемнение `rgba(13,27,75,.55)` с «дыркой» под якорем (четыре прямоугольника или `box-shadow` на клоне-рамке), якорь прокручивается в видимую область (`scrollIntoView({block:'center'})`), облачко — белая карточка `--radius`, заголовок, текст, внизу «Пропустить» слева, «Назад» / «Далее» справа, счётчик «5 / 23». Полноэкранный шаг — карточка по центру, до 720 px, плитки сеткой 2–3 в ряд (на телефоне — в столбец). `z-index` выше `--z-overlay` (выше полосы и модалок). Фокус — внутрь карточки, `Esc` = «Пропустить», стрелки ←/→ = Назад/Далее. Телефон: облачко снизу экрана на всю ширину, подсветка сверху.
4. **Запуск.** Переменная окружения `TOUR_AUTOSTART` = `always` | `first` | `off` (по умолчанию `first`; **на проде до демо — `always`**). Сервер отдаёт в шаблон `tour_mode` и `tour_id` для пользователя: `employee` → `employee`-тур на `/cabinet`; `hr_lead` → `hr_lead`-тур на дашборде роли; остальным ролям автозапуска нет. `always` — тур стартует при каждом входе на стартовой странице; `first` — пока у пользователя пуст `User.tour_seen_at` (новая колонка, nullable; ставится по «Готово»/«Пропустить» через `POST /tour/seen`); `off` — никогда. Тур стартует **только на `start_url`**: на внутренней странице без активного состояния в `sessionStorage` он не появляется.
5. **Кнопка «?»** в шапке (`topbar`, и в кабинете сотрудника) — всегда, независимо от режима; ведёт на `start_url` с `?tour=1`, что принудительно запускает тур с первого шага. «Пропустить» в режиме `always` закрывает до следующего входа (флаг в `sessionStorage`), в `first` — ставит `tour_seen_at`.
6. **Якоря** — атрибуты `data-tour="<anchor>"` на существующих элементах (ничего не оборачивать). Список по турам — в блоках B и C; если элемент уже имеет `id`, якорь всё равно ставится атрибутом, чтобы JSON не зависел от вёрстки.

## Блок D — доработки кабинета сотрудника (чтобы тур не обещал лишнего)

1. **«От компании» в «Мои документы»** (`/employee_docs`): блок со списком документов этого сотрудника типов «ТРУДОВОЙ ДОГОВОР», «ХОДАТАЙСТВО», «РЕКОМЕНДАТЕЛЬНОЕ ПИСЬМО» (по `EmployeeDocument` с файлом), каждый — название, дата, кнопка «Скачать» через существующий маршрут выдачи файла с проверкой `documents.own` (сотрудник видит только своё). Пусто → «Документы от компании появятся здесь».
2. **«Поддержка»** (`/support`): вместо заглушки — страница с карточкой «Ваш менеджер: ФИО, телефон» (по `tm_id`; телефон кликабелен `tel:`; нет ТМ — «менеджер пока не назначен») и шестью вопросами-ответами как `<details>`: где смотреть часы; что значит «смена без плана»; как загрузить документ; когда выплаты (аванс еженедельно, табель 1–15 и 16–конец); как сменить пароль; к кому обращаться по реквизитам. Тексты — в шаблоне, без базы.
3. **«Вакансии»** (`/vacancies`): заглушка остаётся, текст — «Открытые вакансии рядом с вами — списком и точками на карте. Раздел запускаем следующим.» с иконкой карты.

## Тесты
JSON туров валидны и у каждого `element`-шага якорь существует в соответствующем шаблоне (тест рендерит страницы под нужной ролью и ищет `data-tour`); `TOUR_AUTOSTART` три режима; `tour_seen_at` ставится по `POST /tour/seen`; `?tour=1` запускает при `off`; сотрудник не получает `hr_lead`-тур и наоборот; «От компании» показывает только свои документы; `/support` с ТМ и без; подпись роли «Руководитель» в `ROLE_LABELS`.

## Приёмка
На проде с `TOUR_AUTOSTART=always`: вход руководителем — обложка, роли, 23 шага с переходами по пяти страницам, «?» повторяет; вход сотрудником — 9 шагов по кабинету; «Мои документы» показывают договор/рекомендацию от компании; «Поддержка» — менеджер и вопросы; оба тура с «Пропустить» закрываются до следующего входа.
