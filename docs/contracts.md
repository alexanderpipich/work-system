# Договоры, ходатайства, рекомендательные письма: генератор

Трудовой договор, ходатайство в УВМ и рекомендательное письмо (П4.11) генерируются по шаблонам владельца из `data/templates/`:

| Файл | Назначение |
|---|---|
| `contract_template.docx` | Рабочий шаблон договора — по нему идёт генерация |
| `contract_template.annotated.docx` | Тот же шаблон с ремаркой разработчику (голубая подсветка) — для справки, в генерацию не идёт |
| `petition_template.docx` | Ходатайство (ремарок нет) |
| `recommendation_template.docx` | Рекомендательное письмо. Тело безличное: без имени и местоимений по полу, ФИО — один раз, в им. падеже |

Код:
- `contract_generator.py` — подстановка в .docx (порт генератора УТКИ);
- `contract_data.py` — откуда берётся каждое поле и проверка полноты;
- `employee_profile.py` — данные сотрудника (поля `User` и его документы);
- `routers/contracts.py` — экран «Договоры» и форма.

## Правило: документы сотрудника — источник данных

Паспорт, СНИЛС и патент берутся из документов сотрудника (`EmployeeDocument`), остальное — из карточки (`User`), юрлица (`LegalEntity`) и региона (`Region`). Если чего-то не хватает, недостающее вводится в форме проверки полноты и **сохраняется в источник**: в карточку, документ, юрлицо или регион. В сам договор вручную ничего не правится.

**Юрлицо бланка** (договор, ходатайство, рекомендация) подставляется так: юрлицо из карточки сотрудника → активное юрлицо с флажком «По умолчанию для документов» (`LegalEntity.is_default`, на `/admin/legal-entities`; флажок стоит только у одного юрлица — при установке снимается у остальных) → единственное активное юрлицо → не выбрано. В выпадающем списке формы — все активные юрлица, юрлицо по умолчанию первым; ручной выбор и перепроверка формы при смене юрлица работают как раньше.

### Как хранится патент

У типа документа два дополнительных поля, а данных патента четыре. Поэтому:

| Поле `EmployeeDocument` | Что хранит | Пример |
|---|---|---|
| `document_number` | серия, номер патента и бланк | `78 №2600131320 / ПР 8408114` |
| `issue_date` | дата выдачи | 18.08.2026 |
| `expiry_date` | срок действия; если пусто — считается «год минус день» от выдачи | 17.08.2027 |
| `extra_field_1_value` | «Орган выдачи» | ГУ МВД России по г. Санкт-Петербургу и Ленинградской области |
| `extra_field_2_value` | «Профессия по патенту» | подсобный рабочий |

Паспорт: `document_number`, `issue_date`, `extra_field_1_value` («Кем выдан»). СНИЛС: `document_number`.

Патент нужен, только если его требуют правила режима гражданства (`RegimeDocumentRule`). У граждан РФ и ЕАЭС строка патента из договора удаляется.

## Карта подстановок: трудовой договор

| Поле договора | Образец в шаблоне | Источник |
|---|---|---|
| Город (шапка) | `г. Санкт-Петербург` | ввод; по умолчанию — `Region.patent_territory` |
| Дата договора (шапка) | `08 октября 2026 г` | ввод (по умолчанию сегодня) |
| Полное имя работодателя | `Общество с ограниченной ответственностью «БАЛТИЙСКИЙ ДОМ»` | `LegalEntity.full_name` |
| «далее ООО «…»» | `ООО «БАЛТИЙСКИЙ ДОМ»` | `LegalEntity.short_name` (или `name`) |
| Должность руководителя | `генерального директора` | `LegalEntity.director_title` |
| Руководитель (род. падеж) | `Хацкевич Виталия Сергеевича` | `LegalEntity.director_name_genitive` |
| Работник | `гражданка Республики Узбекистана Отабоева…` | «гражданин/гражданка» по `User.gender` (или угадано по отчеству) + `Country.name_genitive` + ФИО |
| 1.1 Должность | `подсобный рабочий` | ввод; по умолчанию — при патенте профессия из патента, без патента — расшифровка кода `User.job_title` (`models.JOB_TITLE_NAMES`, им. падеж: РТЗ → «работник торгового зала»). Должности в карточке нет или у кода нет расшифровки (ПЕКАРНЯ, ГАСТРОНОМ) — поле пустое, в недостающих |
| 1.3 Место работы (в шаблоне не подсвечено) | `г. Санкт-Петербург, ул. Бабушкина д.40` | `Store.object_address` магазина, где сотрудник чаще выходил за 14 дней (`contract_data.recent_work`: смен больше → часов больше → смена позже; смены без плана и услуги «не из timebook» не считаются); подсказка «ТК 660, 9 из 11 смен; также ТК 623, 2 смены». Нет адреса у магазина — поле в недостающих, ввод сохраняется в карточку магазина. Смен за 14 дней нет или ТК нет в справочнике — `LegalEntity.work_address` |
| 1.5 Вступает в силу / начало работы | `08 октября 2026 года` (×2) | ввод (по умолчанию = дата договора) |
| 1.6 Срок | `на неопределенный срок./ на срок до «дата окончания патента»` | ввод. Без патента — бессрочный или «на срок до …». С патентом — только срочный: «бессрочный» в форме не предлагается, срок по умолчанию = окончание патента, дата позже него и `term_indefinite=1` отклоняются |
| 5.1 Ставка (в шаблоне не подсвечено) | `232,18 (двести тридцать два) рублей 18 копейка` | ввод; если пусто — самая частая ЧТС по сменам за 14 дней через `price_shift`, как в выплатах (индивидуальные ставки, регион ТК), **без «Акции»**: больше смен → больше часов, смены без ЧТС не считаются; формат «333,00», подсказка «ЧТС по 12 из 14 смен; также 338 — 2 смены». Смен со ставкой нет — поле пустое, в недостающих. Прописью: «232,18 (двести тридцать два) рубля 18 копеек» |
| Реквизиты работодателя | краткое имя, юр. адрес, ИНН/КПП, ОГРН, р/с, банк, БИК, к/с, подпись `В.С. Хацкевич` | `LegalEntity` |
| ФИО работника (таблица) | `Отабоева Навбахор Исломбой Кизи` | `User.employee_name` |
| Дата рождения | `21.03.1998` | `User.birth_date` |
| Паспорт | `№FA9061607 выдан 25.01.2024` | документ «Паспорт» (+ «кем выдан», если заполнено) |
| ИНН | `780114424010` | `User.inn` |
| СНИЛС | `229-798-702 37` | документ «СНИЛС» |
| Патент | вся строка «Патент серия … срок действия патента …» | документ «ПАТЕНТ»; орган — из документа или `Region.patent_authority` |
| Подписи | `Отабоева Н.И.` (×2) | инициалы из ФИО |
| Дата получения экземпляра | `8 октября 2026 года` | дата договора |

|---|---|---|
| Работодатель (голубое) | `Общество с ограниченной ответственностью «ЦКК»`, ОГРН, КПП, ИНН, юр. и факт. адрес | `LegalEntity` (`full_name`, `ogrn`, `kpp`, `inn`, `legal_address`, `actual_address`) |
| Подпись руководителя | `Бигильдин Тимур Ривкатевич` | `LegalEntity.director_name` |
| Адресат (зелёное) | `Начальнику УВМ ГУ МВД России` / `По Санкт-Петербургу и Ленинградской области` | `Region.uvm_addressee` — делится на две строки по первому « по » |
| Звание, ФИО начальника | `Полковнику полиции`, `Иванову Ивану Васильевичу` | `Region.uvm_rank`, `Region.uvm_person` |
| ФИО сотрудника, патент (жёлтое) | ФИО, серия/номер, бланк, срок «с … по …», дата выдачи, кем выдан, профессия | сотрудник и документ «ПАТЕНТ» |
| Территория патента | `г.Санкт-Петербург` | `Region.patent_territory` |
| Дата | `«09» июня 2026 г` | ввод (по умолчанию сегодня) |

Если у региона не заполнен адресат, форма предлагает заполнить его на месте (сохраняется в справочник `/admin/regions`). Запасной вариант — генерация с «НЕТ ДАННЫХ».

## Карта подстановок: рекомендательное письмо

Кнопка «Создать рекомендацию» на `/admin/contracts` — у каждого сотрудника, форма `kind=recommendation` (юрлицо, город, должность, дата; региона и номера нет). Документ сохраняется у сотрудника с типом «РЕКОМЕНДАТЕЛЬНОЕ ПИСЬМО». Если на проде этого типа ещё нет, он заводится сам из `data/reference/document_types.json`.

| Поле | Образец в шаблоне | Источник |
|---|---|---|
| Шапка | `Общество с ограниченной ответственностью ООО УК "АЛЬЯНС"`, ОГРН, КПП, ИНН, фактический адрес | `LegalEntity` (`full_name`, `ogrn`, `kpp`, `inn`, `actual_address`) |
| ФИО (им. падеж, один раз) | `Иванов Иван Иванович` | `User.employee_name` |
| Город работы | `г. Санкт-Петербург` | ввод; по умолчанию — `Region.patent_territory` региона по последним сменам |
| Должность | `работник торгового зала` (в кавычках «…» — без склонения) | ввод; по умолчанию — профессия из патента, иначе расшифровка кода `User.job_title` (`JOB_TITLE_NAMES`) |
| Подписант | `Директор ООО УК "АЛЬЯНС"` | `LegalEntity.director_title` в им. падеже (`signer_title`: «генерального директора» → «Генеральный директор») + `short_name` |
| ФИО руководителя | `Шестак Сергей Николаевич` | `LegalEntity.director_name` |
| Дата | `«13» октября 2026 г` | ввод (по умолчанию сегодня) |

Подписант ООО УК «АЛЬЯНС» — это данные владельца, а не код: юрлицо заводится на `/admin/legal-entities` с заполненными `director_title` и `director_name`.

## Как работает подстановка

Для каждого поля в карте (`CONTRACT_SUBS`, `PETITION_SUBS`, `RECOMMENDATION_SUBS` в `contract_generator.py`) заданы:
- **якорь** — кусок постоянного текста, по которому находится абзац;
- **образец** — текст из шаблона, который заменяется.

Образец может быть разбит в Word на несколько runs. Замена всё равно найдёт его и не испортит форматирование соседнего текста. Подставленное выделяется в отдельный run и подсвечивается **жёлтым**, подсветка шаблона снимается. Если значения нет, подставляется «НЕТ ДАННЫХ» (тоже жёлтым) — только когда нажато «Сгенерировать, пропустив недостающее».

## Как обновлять шаблон

1. Текст шаблона менять можно.
2. **Образцы и якоря из карты должны остаться в шаблоне дословно** (например, `Отабоева Навбахор Исломбой Кизи`, `08 октября 2026 года`, `ИНН/КПП:`). Если поменяли образец, поменяйте его и в `contract_generator.py`.
3. Подсветку менять можно: генератор ищет текст, а не цвет.
4. Проверка после правки:

   ```bash
   pytest -q tests/test_documents_contracts.py -k real_templates
   pytest -q tests/test_predemo_p411.py -k template_samples   # рекомендательное письмо
   ```

   Тест подставляет значение в каждое поле шаблонов. Если образец или якорь пропал, тест падает с `TemplateMismatch` и пишет, какого именно не нашлось.
5. Ремарки разработчику (голубая подсветка в договоре) держите в `contract_template.annotated.docx`. Из рабочего шаблона их нужно убрать: генератор их не трогает, и они попали бы в договор.
